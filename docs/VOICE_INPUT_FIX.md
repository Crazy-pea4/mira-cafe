# 真实语音入口修复（2026-10-25）

用户反馈：“按住体验那个按钮有问题，不识别我的语言”。

根因：前端 inputMode 固定初始为 mock，健康接口 speechAvailable=true 只启用隐藏选项，没有改变主入口。因此主按钮仍显示“按住体验”，松手发送的是预设文字，没有调用 ASR。诊断开始时健康接口确认 DeepSeek/Qwen 均已启用。

同时用假设备复现了两个手势问题：首次权限弹窗可能触发页面失焦/释放，取消正在初始化的采集；已有有效音频但 WebSocket 未就绪时松手，旧 finish() 直接放弃整段录音。

## 修复

- 页面读取健康状态后，已配置真实语音自动选择真实入口；检查期间按钮禁用，服务状态失败/预算阻塞时不悄悄退回模拟。
- 首次“启用麦克风”是独立权限步骤：用户明确点击才请求权限，取得流后立即停止所有轨道，不启动 AudioWorklet 或 ASR。权限弹窗引发失焦不会取消这个步骤；允许后明确提示重新按住说话，不自动录音。
- 授权后主按钮“按住说话”，准备中、录音中、松开识别、识别中分别显示。键盘与指针共用状态，松手后的 lostpointercapture 不取消已提交识别。
- 松开先停止采集并冲刷尾帧；已有有效PCM会保留到连接就绪，再仅提交一次。新录音、失焦、取消会使迟到响应失效。
- 初始化最多8秒，录音仍最多30秒；短于250ms/空白/异常结果不提交LLM。工作线程加载失败会释放流和AudioContext。
- 模拟入口仅在明确选择或无真实配置时使用，改名“模拟台词／不识别讲话”，避免误解。
