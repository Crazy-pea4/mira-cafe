## 修复及证据边界

- 事件停滞：原事件导演完全依赖可选模型beat，实际聊照片而不附beat时，道具永远不动。现在依据已呈现前置条件与当前照片/风/窗/门话题补齐外部事件，拒绝/歧义/设定玩笑不强推。手机事件在照片已呈现且玩家回应后可发生。没有固定计时器、轮数升级或代用户作决定；事件仍需实际呈现回执。
- 提前暗示消息：本地非咖啡闲聊fallback无条件带“消息”。现在先检查phone-message是否已呈现。
- 照片校验：代码可确定存在“允许reveal-photo但缺外部beat就拒绝”和“仅拍摄年份也视为完整隐情泄露”两类冲突。按同一前置规则放行可由本地导演补齐的照片事件；地点/年份可自然回答，不计为两天没说话的完整memory事实。真正隐情、未呈现委托和结局前置仍校验。合成fixture穿过真实DeepSeekProvider/重试/导演覆盖两类冲突；最终真实照片问题通过。缺少原始失败内容，因此不把某个具体子条件写成已证实的唯一现场根因。
