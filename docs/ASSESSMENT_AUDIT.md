# Mira Café 考核要求核对

核对日期：2026-10-27。依据原始六页PDF《72小时实验：实时互动场景产品》，覆盖核心体验、交付材料及全部29条可选扩展。岗位职责中的支付、社区、ComfyUI等不替代本题范围；本题明确不要求完整账号、支付、后台、社区或大规模基础设施。

当前核心链路已有实现与自动化、浏览器、真实API记录；剩余工作主要是实机验收、交付材料完善，以及若干部分实现或未选择的可选扩展。ComfyUI仅有适配层，不能计为动态生成媒体完成。

本次新增SQLite和只读剧情轨迹并完成Mock、自动化及部署验证（详见统一验收）；原始审查阶段曾重新提取并查看原题相关页面，核对视频时长及Git状态。此前SQLite阶段未新增付费调用；2026-10-27已单独补录真实链路，费用次数及边界见[录屏说明](DEMO_VIDEO.md)。运行证据沿用[交付验收](RELEASE_ACCEPTANCE.md)、[部署状态](DEPLOYMENT_STATUS.md)和对应专题记录。

## 状态口径

- **已实现**：存在相应代码与既有验证记录，不代表所有设备或真人体验已验收。
- **部分实现**：覆盖部分场景，或只有基础机制，不能承诺完整能力。
- **未实现**：当前没有可运行的对应产品能力；接口、素材和方案不能替代闭环。
- **待验收或交付**：实现或文件已存在，但还需要真人确认、同步仓库或提供材料。

可选扩展不是必须全部完成。下表逐项列出其缺口，不把未选的视频和生成媒体路线算作核心体验缺失。

2. **完成实机验收。** 手机登录、授权、讲一句、听回复、再次开口/按住打断；检查软键盘、安全区、耳机与外放、后台和网络恢复。记录设备、浏览器、现象及是否通过。
3. **用已补齐的R5/E6基础面板定位实际等待。** 当前已有识别、模型首字、TTS首包和实际开播的计时及阶段状态；下一步根据实机结果优化，而非把替身耗时当成真实性能。
4. **再完善R2、R3、R6及E3。** 根据实测调整附和、噪声、回声与恢复策略，统一记录轮次关联事件；自动重连时避免重复提交录音或付费请求。
5. **表演方向按目标升级。** 先改善当前表情与姿态切换，再评估音频驱动、配置协议或Live2D；未选择Live2D本身不构成核心缺项。
6. **生成媒体与视频方向择一再做。** 若要证明岗位要求中的ComfyUI实操，需要真实工作流与生成/存储/展示闭环，单有适配器不足；题目本身不强制ComfyUI，也不要求把29条扩展全部实现。

前三项优先级是本次核对建议，不表示已经开始新增功能。
