# SQLite 持久化

项目使用Node内置`node:sqlite`，不新增数据库服务、容器或原生npm依赖。最低Node 22.13；本地Node24.22.1/SQLite3.53.4、服务器Node22.23.2/SQLite3.51.3已核对。Node22中该接口仍为实验状态，数据访问集中在仓库层，不向业务散布驱动细节。

## 数据与关系

| 表 | 用途 |
| --- | --- |
| schema_migrations | 按版本在事务中执行迁移 |
| visitors | 匿名浏览器身份，只保存随机身份令牌的摘要 |
| auth_sessions | 邀请登录令牌摘要、所属浏览器、凭据版本摘要与8小时过期时间 |
| conversations | 按浏览器与模式隔离的剧情状态、显示存档、版本和归档标记 |
| conversation_messages | 按会话/轮次/角色保存已确认呈现的消息，唯一约束防止回执重传重复写入 |
| usage_totals | 请求统计，事务更新；不代表账单，也不增加金额拦截 |
| reply_diagnostics | 有界结构化诊断，不存模型原文、系统提示词或凭据 |
| client_timings | 浏览器阶段耗时数值，按身份和模式隔离，每个范围保留最近200条 |
| legacy_imports | 文件统计、诊断的幂等导入标记 |

表结构使用STRICT、外键、唯一约束和查询索引。查询参数绑定；短写入采用事务和版本条件更新，避免其他页面或重置后的旧回执覆盖新进度。SQLite启用WAL、外键、FULL同步和有限忙等待。

## 存档与身份

正式页面先加载数据库进度再开放交互。呈现回执确认对白/事件后，剧情状态、显示快照与消息在同一事务保存；正在生成或尚未完成的一句不会成为正式事实。客户端localStorage只作为可丢弃缓存和旧版本迁移来源。

数据库为空时，浏览器旧存档须通过签名校验后才能导入，已有进度不被旧缓存覆盖。重置会归档旧会话并创建新会话，之后不再接受该浏览器的旧版导入，迟到回执也无法恢复旧剧情。

匿名身份通过HttpOnly、SameSite=Strict Cookie区分，线上追加Secure。邀请会话关联稳定匿名身份，退出后重新登录可续接；服务重启不再清空有效登录。登录令牌仍固定8小时到期，退出立即撤销，邀请密码更换后凭据版本不匹配的旧登录失效。没有新增注册或个人账号。

同一邀请密码不会让不同浏览器看到彼此的数据。清空localStorage仍可凭Cookie恢复数据库存档；清除身份Cookie后会成为新访客，没有账号找回或跨设备同步。

## 路径与迁移

- 本地Docker：状态卷内`/var/lib/mira-cafe/mira.sqlite`。
- 服务器：既有`/var/lib/mira-cafe/mira.sqlite`，不随release目录替换。
- 本机Node诊断：默认`.local/mira.sqlite`，所有SQLite及WAL/SHM文件被Git忽略。
- API密钥、邀请密码配置与签名密钥继续独立保管，不放入业务数据库。
- 旧budget.json与格式诊断只导入一次，不删除原文件；坏统计保留异常状态，不冒充零用量。历史防重复收费标记不迁移、不清除。

备份应使用SQLite一致性备份机制，或在停服并完成检查点后进行；不能在运行中只复制主文件而忽略WAL。备份同样含私人会话内容，保持受限权限，不提交仓库。

## 接口与边界

`GET api/progress`恢复当前浏览器进度；`POST api/progress`仅用于签名旧存档的一次导入；`DELETE api/progress`重置。`POST api/presented`推进并事务保存正式剧情。`POST/GET api/timings`保存/读取当前身份的数值历史。写操作检查Origin，API沿用邀请保护。

取消信号、播放器、未完成回复、短期连接及登录失败节流仍属于运行时状态，留在内存。图片、视频和原始音频不放数据库。数据量及并发仍按单机Demo设计，不承诺多机数据库共享。

入口：[database](../server/database.ts)、[迁移](../server/migrations/001-storage.ts)、[确认显示快照](../server/persisted-progress.ts)、[数据库测试](../tests/database.test.ts)。
